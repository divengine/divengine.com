Get Divengine Studio

Studio is not a service you sign up for. It is free software you download and run on your own infrastructure: a laptop to try it, a server for your team, your cloud of choice. Your data never leaves it.

Download the sourceInstallation reference

What you need

Install with the web installer

This is the recommended path. The installer is a Drupal installation profile with the Studio branding; the recipes in the repository define what it installs.

  1. Get the code

    git clone {{repo}}.git
cd studio
composer install

  2. Create the database

    An empty PostgreSQL database with pg_trgm enabled.

    sudo -u postgres psql <<'SQL'
CREATE ROLE studio LOGIN PASSWORD 'choose-a-good-one';
CREATE DATABASE studio OWNER studio;
\c studio
CREATE EXTENSION IF NOT EXISTS pg_trgm;
SQL

  3. Prepare settings.php

    Set the private file path and the host names Studio will answer to.

    cp web/sites/default/default.settings.php web/sites/default/settings.php
mkdir -p private/files
cat >> web/sites/default/settings.php <<'PHP'
$settings['file_private_path'] = '../private/files';
$settings['trusted_host_patterns'] = ['^studio\.example\.com$'];
PHP

  4. Configure the web server

    Point it at web/. Only Apache reads Drupal's .htaccess rules; on nginx or Caddy, deny settings files, source files, hidden files and PHP under files/ yourself. The Studio README has ready-made nginx and Caddy configurations.

  5. Open the installer

    Browse to https://studio.example.com/core/install.php. The Divengine Studio distribution is selected automatically. Choose a language, enter the database, choose optional integrations (MCP integration is off by default) and create the administrator account. When it finishes, Studio opens on My work.

  6. Optional: connect AI assistants

    If you selected the MCP integration, create its service account and token on the server:

    vendor/bin/drush divengine:mcp-setup --uri=https://studio.example.com

    The token is written to a private file, never printed, and the command shows how to connect a client. Add the service account to the Developments it should read.

Without a browser

The same profile installs from the command line, for example in provisioning scripts:

vendor/bin/drush site:install divengine_studio_installer \
  --db-url=pgsql://studio:choose-a-good-one@localhost/studio \
  --site-name='Divengine Studio' \
  --account-name=admin --account-mail=you@example.com
# add divengine_studio_installer_integrations_form.mcp=1 for MCP

Apply Studio to an existing Drupal 11 site

The recipe that the installer applies can also be applied to an existing Drupal 11 site, such as a Standard installation. The site keeps its name; /studio becomes the front page, the Studio theme the default theme and Gin the administration theme.

vendor/bin/drush recipe $PWD/recipes/divengine_studio
vendor/bin/drush recipe $PWD/recipes/divengine_studio_mcp   # optional

Updating an installation

Studio is under active development and has no tagged releases yet; a versioned release and upgrade policy is being prepared. Until then, treat updates as you would for any Drupal site:

  • Back up the database and the private files directory first
  • Pull the new code, run composer install, then drush updatedb and drush cache:rebuild
  • Sites installed earlier from the recipe need no migration to the installer profile. Re-applying the recipe adds configuration they lack and leaves existing configuration untouched
  • Try the update on a copy of your site before production
