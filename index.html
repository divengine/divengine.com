About

What is Divengine?

Divengine is an open source, self hosted software engineering platform and process focused on explicit, traceable engineering work.

It is not an IDE and does not replace Git; code remains in source control while the platform links intent, models, decisions, activities, and outcomes.

The same platform is usable in production teams and for teaching software engineering, because artifacts and decisions are explicit and inspectable.

Methodology describes how engineering is reasoned, process describes how work flows, and the platform executes and automates it.

GitHub

GitHub as the engineering backbone

GitHub is the primary collaboration, code, and governance hub for the platform.

Source code lives in GitHub. Documentation lives in GitHub as Markdown, diagrams, and specifications. Issues represent engineering work items. Discussions capture design and reasoning. Pull requests represent controlled change. Releases represent validated milestones.

All domains and artifacts shown on this page are mapped or mappable to these GitHub artifacts so work remains transparent and auditable.

Use

Production and education

The platform is usable in production environments where engineering work must be explicit, traceable, and auditable.

The same platform is suitable for teaching software engineering by working with explicit artifacts and decisions. Engineering discipline is taught by doing, not by slides, and the platform supports practice without replacing courses.

Domains

Engineering domains covered

Each domain below represents concrete software engineering work the platform brings together in one environment, mapped to GitHub artifacts for traceability.

Engineering Process & Planning

Intent, goals, and constraints link to activities and tasks through Kanban and Gantt style views, with traceability from intent to work. This is engineering planning, not a project management tool.

Requirements & Business Modeling

User stories, structured requirements, BPMN flows, and business rules are captured as explicit, auditable engineering artifacts.

Modeling & Architecture

UML class and use case models and architectural views capture system design, while keeping system and business concerns distinct.

Formal Specification & Validation

Formal specifications, including TLA+ where appropriate, support reasoning, simulation, and early error detection.

Documentation & Knowledge

Documentation led workflows and knowledge maps keep project context explicit and connected to engineering work.

Execution & Integration

Connections to version control workflows and CI/CD remain external but traceable, with APIs for integrating external systems. Divengine orchestrates, not replaces.

Early feedback

Earlier specification, modeling, and validation surface errors sooner and reduce production failures.

Planning is grounded in engineering activities and artifacts, improving use of engineering time and people.

Work beyond code such as analysis, modeling, and documentation becomes visible and auditable, supporting better cost control, fairer compensation, and less dependency on tribal knowledge.

Divengine is not accounting software; it exposes APIs so other systems can measure effort and workflow metrics, which supports faster onboarding of engineers and reporting.

Projects operate under real constraints of people, time, and computing resources. The platform is designed to reduce cost, late failures, and wasted effort by making software engineering work explicit.

Standards

Aligned with industry standards

Divengine aligns with recognized software engineering standards as guidance for structure, artifacts, and traceability.

Reference points include ISO/IEC 12207 and ISO/IEC 15288 for lifecycle and process guidance, and ISO/IEC 25010 for quality characteristics.

The platform supports requirements, documentation, and traceability practices, and modeling and specification approaches such as UML, BPMN, SysML, and formal methods, including TLA+ where appropriate.

Organizations can map their own compliance requirements onto the platform. Audits and certification remain external.

Workflow

How it works

Spec -> Action pipeline

A typical flow can move from needs and intentions to models and deterministic outputs.

Step 1 - Start from a real world problem

Intent emerges from need. Divengine can turn it into branches, tasks, docs.

Step 2 - Model -> Deterministic Outputs

Requirements, architecture, structure, workflows generate templates, docs, scaffolds.

Step 3 - Orchestrate Your Tools

Divengine can sync branches, tasks, docs, CI/CD automatically.
